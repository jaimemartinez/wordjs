### [ ] H1. Composed footer nav is painted with the HEADER's nav colour — `.wjs-chrome-nav a` is location-blind
- **promesa**: frontend/src/components/chrome/ChromeNav.tsx:12 — `footer: "text-[var(--wjs-color-text-footer-dim,gray)] hover:text-[var(--wjs-color-primary,white)]"`. - **fallo**: Theme cobalt-corporate ships marketplace/themes/cobalt-corporate/chrome/footer.json containing `{"type":"ChromeNav","props":{"location":"footer","orientation":"vertical"}}`. Its style.css:305 sets `--wjs-nav-color: #363637` (near-black, meant for the light masthead) and style.css:37 sets `--wjs-color-text-footer-dim: #7f92b3` (the legible blue-grey it actually wants in the footer). The footer link column renders #363637 on the dark footer surface (`--wjs-bg-footer` default rgb(17,24,39), wordjs-ui.css:102) — effectively invisible, while the token the theme explicitly set for that job is discarded.

### [ ] H4. layout.header.transparent is a dead flag in the default chrome whenever header.sticky is true (the default)
- **promesa**: backend/public/theme-layouts.schema.json:22-26 declares `header.transparent` (default false): "true = header without background over the start of the page until the first scroll (background returns with data-scrolled)" — so false must mean the header IS painted at the top. documentation/themes.md:187 repeats it. frontend/src/components/public/PublicLayoutShell.tsx:94 dutifully forwards `transparent={header.transparent}` to Header.
- **realidad**: frontend/src/components/public/Header.tsx:152 — `const topBg = transparent ? "bg-transparent py-6" : (disableSticky || !sticky ? scrolledBg : "bg-transparent py-6");`. Both arms of the ternary are the SAME string once `sticky` is true and `disableSticky` is false, and nothing on the live site ever passes `disableSticky` (PublicLayoutShell.tsx:94 omits it; Header.tsx:21 defaults it to false). So for every sticky header the flag selects between two identical class lists — it is read and thrown away. It only has any effect in the `sticky:false` branch. No test covers it: frontend/src/lib/__tests__/themeLayout.test.ts only asserts the parser (lines 22-37), never the rendering.
- **fallo**: A theme with a header bar whose colour differs from the page canvas — i.e. `--wjs-bg-surface-glass` != `--wjs-bg-canvas`, the normal case for a coloured/dark header over a light page — sets `layout.header = { sticky: true, transparent: false }` and still gets NO header background, NO backdrop-blur and NO shadow over the first ~10px of scroll: the nav floats over the page canvas and the whole bar pops in the moment the visitor scrolls. There is no way to opt out. Four shipped themes declare exactly `sticky:true, transparent:false` AND have no chrome/header.json, so they run this path: marketplace/themes/japandi-haven (theme.json:8-12), marketplace/themes/noir-or, marketplace/themes/verdant-studio and backend/themes/herbario; today they only mask the colour half of it by setting surface-glass == canvas, but the `shadow-sm`/`backdrop-blur-md` still appear only after scrolling.
